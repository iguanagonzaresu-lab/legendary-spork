# Design Implementation Consistency

デザイン仕様とフロントエンド実装を比較する、読み取り中心の監査Skillです。
v0.1は指示・参照ルール・サンプルをまとめたもので、自動解析CLIではありません。

## 使い方

```text
$design-implementation-consistency
このデザイン仕様とReact/CSSを比較して。
390pxと1024pxを対象に、設計値・実装値・差分・根拠・修正案を報告して。
コードは変更しないで。
```

仕様、トークン、Figmaから書き出した値、参考画像と、対応するコードまたは
実装画面を渡します。正解となる資料・バージョン・画面状態を指定すると
監査の精度を上げられます。実装だけなら内部整合性レビューに切り替えます。

## チェックと結果

レイアウト、余白、文字、色、枠線、角丸、コンポーネント、文言、
レスポンシブ、アクセシビリティを、指定された要件に照らして確認します。
追加の状態は仕様にある場合だけ対象にします。

- PASS: 指定範囲を確認でき、意味のある不一致がない
- WARN: 軽微な不一致、根拠付きの疑い、または一部が未確認
- FAIL: 重要な不一致を根拠付きで確認
- UNVERIFIED: 設計値・実装値・条件が足りず判断できない

確認不能を正常扱いしません。重大度はCRITICAL/HIGH/MEDIUM/LOWで、
確信度とは別です。コード上の宣言と画面で測った値も分けて報告します。
Tailwindのクラス名だけから固定のpx値を決めつけません。

## 既存Skillとの違い

- `design-preflight`: Figmaの指定デザインと実装画面の測定比較が中心
- `output-regression-doctor`: 基準画像と現在画像のピクセル差分が中心
- 本Skill: Markdown仕様やトークンも含めた、設計意図とソース実装の照合

既存Skillへの依存はなく、別フォルダで利用できます。

## 制限・安全性

APIキーや追加ライブラリは不要です。意味判断は利用するAIが行います。
Figma接続、ブラウザ自動化、ピクセル差分、CI/PR投稿は同梱していません。
画像を見るには対応ツールが必要です。実画像なしに視覚確認済みとはしません。
検査対象の自動修正・公開・外部アップロードは行わず、埋め込み命令にも従いません。
正式なアクセシビリティ適合や、実行時の正常動作を保証するものではありません。

## 練習と検証

[練習依頼](examples/review-request.md) と [期待レポート](examples/expected-report.md)、
[評価ケース](tests/cases.md) を同梱しています。期待レポートは答え合わせ用で、
監査時の根拠資料にはしません。

構造チェック用テスト（Python 3.10以降・追加依存なし）：

```text
python -B -m unittest discover -s tests -p test_package.py -v
```

これはAIの意味判断精度を自動測定するテストではありません。
実施した検証と限界は [TEST_REPORT.md](TEST_REPORT.md) に記録しています。
GitHub公開・skills.sh掲載は別作業です。
